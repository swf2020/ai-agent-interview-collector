### 2.1 E2E 集成测试

#### Test 1: 首次采集全流程 (e2e-fresh-collection)

**测试目标**: 验证从采集到输出的完整 7 步流程正常工作

**前置条件**:
- `web_access` skill 可用（CDP 浏览器模式）
- `samples/` 目录下无历史题集文件（模拟首次采集）
- `references/site-patterns/` 下的小红书/B站/脉脉站点经验文件存在

**输入**:
```
帮我跑一次 AI Agent 面试题采集，时间范围 2026年1月到5月，输出到 samples/ 目录
```

**验证点**:

| # | 检查项 | 验证方式 |
|---|--------|---------|
| 1.1 | Step 1: 5 个平台 Agent 并行启动，各自返回结果 | 检查 Agent 执行日志 |
| 1.2 | Step 2: 去重后题目数 ≤ 原始采集数，上限 200 | 比对 Step 1 和 Step 2 输出 |
| 1.3 | Step 3: 所有题目正确标注 [Module N] / 公司大类 / 轮次 | 人工抽查 20% |
| 1.4 | Step 4: 识别为"初次采集"模式 | 检查日志 |
| 1.5 | Step 5: 生成 `ai_agent_interview_questions_YYYYMMDD.md` | 文件存在且非空 |
| 1.6 | Step 5: 章节标题含 emoji（🎯/📦/⭐） | 全文搜索 |
| 1.7 | Step 6: 每道 AI Agent 题生成解答文件 | `answers/module_*.md` 存在 |
| 1.8 | Step 7: 生成公司文件和 `company_index.md` | 目录结构正确 |
| 1.9 | Step 7.2: 校验报告"全部通过" | 无遗漏链接/文件 |
| 1.10 | 汇报包含平台采集总览 + Agent 执行总览 + 数据统计 | 检查最终输出 |

**预期输出**:
```
samples/
├── ai_agent_interview_questions_YYYYMMDD.md   # 主题集文件
├── company_index.md                            # 公司索引
├── answers/
│   ├── module_01_prompt_llm.md
│   ├── module_02_rag.md
│   ├── module_03_tool_calling.md
│   ├── module_04_agent_architecture.md
│   ├── module_05_multi_agent.md
│   ├── module_06_engineering.md
│   ├── module_07_deployment.md
│   ├── module_08_evolution.md
│   └── module_00_other.md
└── company/
    ├── 互联网公司/{公司名}.md
    ├── 外企/{公司名}.md
    ├── AI公司/{公司名}.md
    ├── 硬件芯片/{公司名}.md
    ├── 创业公司/{公司名}.md
    └── 其他/{公司名}.md
```

## 3. 测试执行方式

### 3.1 E2E 测试（Test 1, 2, 9, 10）

**执行方式**: 通过 Claude Code 主会话拉起 skill，逐一验证

```bash
# 在 Claude Code 中输入测试 prompt
"帮我跑一次 AI Agent 面试题采集，时间范围 2026年1月到5月"
```

**局限性**:
- E2E 测试依赖 `web_access` skill 和 CDP 浏览器，需要真实网络环境
- 小红书/B站 反爬严格，采集成功率不稳定
- 建议在非高峰时段执行

### 3.2 单元测试（Test 3-8）

**执行方式**: 通过 Agent 工具拉起独立 Agent，注入测试数据

```
# 示例：测试 Step 2 清洗去重
Agent prompt: 读取 evals/fixtures/dedup_test_input.md，
按照 SKILL.md Step 2 的规则执行清洗去重
```

**优点**:
- 不依赖外部网络
- 可重复执行
- 结果可精确比对

### 3.3 格式校验（Test 5, 7）

**执行方式**: 结合脚本自动化校验

```python
# 可编写 Python 脚本自动化校验：
# - Markdown 结构完整性
# - emoji 章节标题存在性
# - 链接有效性（检查 A/B/C）
# - 公司标签格式正则匹配
```

## 5. 执行顺序建议

```
Phase 1（单元 - 快速验证）:
  Test 3 (清洗去重) → Test 4 (分类) → Test 5 (输出格式) → Test 6 (解答生成)

Phase 2（边界 - 异常覆盖）:
  Test 8 (传统SE题) → Test 10 (全部无结果) → Test 9 (部分失败)

Phase 3（E2E - 集成验证）:
  Test 1 (首次采集) → Test 7 (索引校验) → Test 2 (增量更新)
```

Phase 1 和 Phase 2 可并行执行（互不依赖），Phase 3 依赖前两阶段通过。
